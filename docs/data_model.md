# Data Model

The target data model is split by ownership:

```text
MySQL source → Debezium/Kafka/Apicurio → Spark Bronze → Spark Silver/Iceberg
                                                    ↓
                                      ClickHouse serving ← dbt
```

## Source and CDC contracts

The source contract covers customers, geolocation, order items, payments,
reviews, orders, products, sellers and product-category translation. MySQL
owns source schema and simulator DML. Debezium and the versioned Avro
contracts own event keys, schema evolution and tombstone framing.

Bronze preserves the transport identity, Confluent schema IDs, payload framing,
transaction metadata and source provenance. Silver applies the entity reader
contracts, deduplicates transport identities and writes normalized Iceberg
tables. Transaction observations are append-only; the serving boundary reads
their effective state.

## Iceberg table families

- `bronze.events` stores captured event metadata and payloads.
- `bronze.avro_schemas` stores schema provenance used for decoding.
- `silver.<entity>_events` stores normalized event history.
- `silver.<entity>_current` stores the latest non-deleted source state.
- `audit.mysql_transactions`, `audit.silver_progress`,
  `audit.normalization_errors` and `audit.schema_violations` store processing
  and rejection evidence.
- `serving.serving_sync_reports` and the serving control tables record bounded
  publication state and rebuild/retry outcomes.

Exact columns, partitions and properties are defined by
`streaming/spark/platform/table_specs.py` and
`docs/plans/lakehouse/contracts/iceberg-data-model.md`.

## ClickHouse serving and dbt

The target dbt project is `dbt/olist_clickhouse`. Its staging models consume
serving CDC/current relations; intermediate allocation models prepare payment
measures; gold models publish the fact, dimensions and revenue marts:

- `fact_order_items` at `order_id + order_item_id` grain;
- `dim_customer_scd2` and `dim_product_scd2` with effective windows;
- `dim_seller`, `dim_date` and `dim_order_status` reference dimensions;
- `mart_daily_revenue` at purchase-date grain;
- `mart_monthly_arpu` at month grain.

dbt owns ClickHouse publication and business assertions. Spark owns event
decoding, normalization, current-state materialization and Iceberg commits.
The serving boundary prevents a publication from crossing an incomplete or
rejected transaction.

## Data-quality rules

The target contracts check source headers, entity keys, schema evolution,
duplicate transport identities, tombstones, Iceberg table definitions,
transaction-state collapse, serving no-op/retry behavior and dbt grain and
measure assertions. The frozen F0 oracle is provenance for parity and is not
regenerated by ordinary CI.
