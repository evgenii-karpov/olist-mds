# Technical contract: Validation & CI

- **Status**: Active normative contract for the target architecture.
- **Purpose**: define mandatory automated checks, bounded integrations, and manual acceptance runs after removing PostgreSQL OLTP/NiFi/the old dbt project.

---

## 1. Validation levels

| Level | Workflow | Trigger | Requirement |
| --- | --- | --- | --- |
| Fast/common | `.github/workflows/ci.yml` | every PR, push to `main` | required branch protection |
| Bounded component contracts | `.github/workflows/lakehouse-components.yml` | PR/push matching target path filters | fast contract jobs required for relevant changes |
| Bounded CDC runtime | `.github/workflows/lakehouse-cdc.yml` | `workflow_dispatch` only | manual bounded CDC acceptance |
| Bounded serving runtime | `.github/workflows/lakehouse-serving.yml` | `workflow_dispatch` only | manual bounded serving acceptance |
| Full acceptance | `.github/workflows/lakehouse-acceptance.yml` | `workflow_dispatch` only | before control-plane transitions, not on every PR |

Frozen baseline F0 is created once and is never regenerated by CI.

The CI-only L3 implementation does not require a full Stage V E2E run: manual
acceptance remains a separate dispatch-only gate. If an L3 change touches
Compose, runtime, DAGs, the dbt project, fixtures, or the Stage V runner, the
boundary changes and the full-run decision must be made separately before launch.

---

## 2. Common CI (`ci.yml`)

The workflow contains a stable aggregate check, `ci-success`, and these jobs:

1. `docs-and-repository-contracts` — syntax/link checks, compileall, fixture/oracle metadata, active legacy references and the independent L4 orphan inventory (`scripts/ci/check_legacy_orphans.py`).
2. `python-quality` — Ruff lint/format and Pyright on target paths.
3. `python-contract-tests` — pytest only for `tests/mysql`, `tests/cdc_contracts`, `tests/lakehouse_platform`, `tests/dbt_clickhouse`, `tests/serving`, and `tests/stage_v`; zero collection is an error.
4. `scala-fast` — scalafmt, compile, ScalaTest, package, and JAR content checks.
5. `compose-contract` — `docker compose config` and static service/profile/image/secret invariants.
6. `airflow-dag-imports` — target image build, no import errors, an exact allowlist of four target DAG IDs (`olist_lakehouse_maintenance`, `olist_lakehouse_serving_sync`, `olist_lakehouse_quality`, `olist_lakehouse_serving_rebuild`) from two target files (`airflow/dags/olist_lakehouse_maintenance.py` and `airflow/dags/olist_lakehouse_serving.py`), and no old dbt path.
7. `dbt-clickhouse-static` — deps, parse, compile, and model/source/selector contracts for `dbt/olist_clickhouse`.

`python -m unittest discover` must not be used as the only test runner: it does not guarantee collection of module-level pytest tests.

---

## 3. Bounded component contracts (`lakehouse-components.yml`)

This workflow contains only fast PR/push checks:

1. `spark-image-contract` — pinned image, offline entrypoint help, JAR/resources/classes, filesystem permissions, and secret leakage;
2. `airflow-runtime` — the same Airflow image, exact DAG inventory, and a bounded task path;
3. `observability-contract` — Compose/config/contract checks for target observability;
4. `component-summary` — summary of only the contract jobs that actually ran.

The workflow has no manual-only jobs or job-level conditions that turn a
mandatory check into `skipped`. It uses path filters, separate Compose project
names, hard timeouts, and cleanup in `always()`. It does not run full V0–V10 or
F1.

---

## 4. Bounded runtime acceptance

Heavy runtime checks are intentionally placed in separate workflows so that they
do not create `skipped` jobs in PR CI and can run independently:

1. `.github/workflows/lakehouse-cdc.yml` — `cdc-component`: bounded MySQL → Debezium → Kafka/Apicurio → Bronze/Silver, initial snapshot, catch-up, and restart;
2. `.github/workflows/lakehouse-serving.yml` — `serving-component`: bounded input, Silver catch-up, finite serving sync, authoritative no-op retry, rebuild, and maintenance path.

Both workflows run only through `workflow_dispatch`, use a small fixture, a
unique Compose project, bounded timeouts, failure diagnostics, artifact evidence,
and cleanup in `always()`. Each workflow has one mandatory runtime job: failure
to complete it successfully means workflow failure.

## 5. Manual acceptance (`lakehouse-acceptance.yml`)

The workflow accepts `suite=candidate-e2e|final-parity|all`, the full `candidate_sha`, and explicit destructive confirmation.

Jobs:

1. `preflight`;
2. `stage-v-e2e` — full clean V0–V10;
3. `final-parity` — candidate-only F1 against the frozen oracle;
4. `publish-evidence` — always runs and does not hide an upstream job failure.

Destructive jobs use a protected environment and a shared concurrency lock. F1 does not start legacy services; this workflow does not modify the F0 oracle.

---

## 6. Required properties of all workflows

- `permissions: contents: read`, unless a job explicitly requires more;
- pinned action versions and dependency caches tied to lockfiles;
- job-level `timeout-minutes`;
- unique `COMPOSE_PROJECT_NAME` per run/attempt;
- upload of JUnit/raw JSON/limited logs on failure;
- Docker resource cleanup in `always()`;
- no secrets in command output, artifacts, or image metadata;
- final status is computed from actual checks; a missing/skipped mandatory check is not `PASS`. The automatic component-contract workflow contains no manual-only runtime jobs, and each dispatch-only bounded runtime workflow fails if its component job does not complete successfully.

## 7. Minimum functional coverage

### Python contracts

- MySQL DDL, users/grants, deterministic seed, and fixture SHA;
- eight CDC topics, the Debezium MySQL connector, and Apicurio compatibility;
- Polaris/Iceberg tables, migrations, Spark config/image, and CLI JSON/redaction;
- Compose profile boundaries and readiness failures;
- serving boundary, transaction state, no-op/retry/rebuild semantics;
- dbt-clickhouse project and native ClickHouse DDL;
- Stage V gate registry, fail-fast behavior, and report integrity.

### Scala

- Confluent framing/schema IDs/references/fingerprints;
- eight entity contracts and Debezium `c/r/u/d/tombstone`;
- UTC/microseconds/decimal normalization;
- event ID/deduplication/order rules;
- idempotent MERGE, partial commits, transaction states, and atomic status output.

### Repository architecture

- no runtime references to NiFi, PostgreSQL OLTP, AWS cloud services/Redshift, the old dbt project, or old Compose profiles; local S3-compatible MinIO endpoints, `s3a://` paths, and Iceberg S3 adapters are allowed as part of the target object-store implementation;
- only documented historical/provenance references are allowed;
- Airflow, dbt, Compose, and documentation use the same target identifiers.

## 8. Retired workflows

The following are removed after the CI cutover:

- `.github/workflows/batch-cdc-parity.yml`;
- `.github/workflows/cdc-stage2-kafka-debezium.yml`;
- `.github/workflows/cdc-stage6-operations.yml`.

Their PostgreSQL/NiFi/raw-CDC scenarios must not remain as optional green checks. Current invariants are transferred to target contract/component suites before removal.
