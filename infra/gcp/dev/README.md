# GCP dev bootstrap and Terraform root

This is the flat Terraform root for the single supported `dev` cloud contour.
It owns APIs, two working GCS buckets, the BigLake Iceberg catalog and
namespaces, five BigQuery datasets, role-specific service accounts, scoped IAM
bindings and optional budget notifications.

The Terraform state bucket is deliberately not managed here. It must be
created manually, versioned, and retained when the main contour is destroyed.
No service-account key is generated by this root.

## Manual bootstrap boundary

Before the first `terraform init`:

1. Create one dedicated GCP project and attach the Free Trial billing account.
   Do not upgrade the account to paid billing.
2. Enable Service Usage for the project and create a dedicated state bucket.
   Keep Object Versioning enabled on this bucket:

   ```powershell
   gcloud services enable serviceusage.googleapis.com --project PROJECT_ID
   gcloud storage buckets create gs://PROJECT_ID-terraform-state `
     --project PROJECT_ID --location us-east1 --uniform-bucket-level-access
   gcloud storage buckets update gs://PROJECT_ID-terraform-state `
     --versioning
   ```

3. Grant the Terraform operator identity access to the state bucket. Record
   the project ID, state bucket name, billing account ID and operator identity
   in the local operator record; do not commit credentials.
4. Authenticate with user gcloud ADC or an approved impersonated ADC file:

   ```powershell
   gcloud auth application-default login
   gcloud auth application-default set-quota-project PROJECT_ID
   ```

The state bucket is the exception to the working-bucket policy. The
lakehouse/checkpoint buckets below are Standard, uniform-access, soft-delete
disabled and Object Versioning disabled, with no lifecycle rules.

## Credential-free validation

From this directory:

```powershell
terraform fmt -check -recursive
terraform init -backend=false
terraform validate
```

`terraform validate` checks configuration only. `terraform plan` and `apply`
require a real project, ADC, enabled APIs and the manually created backend
bucket. Use the repository CLI for the normative lifecycle:

```powershell
uv run python scripts/lab.py gcp preflight
uv run python scripts/lab.py gcp terraform init
uv run python scripts/lab.py gcp terraform plan
```

For a real initialization, pass the state bucket explicitly:

```powershell
terraform init -backend-config="bucket=PROJECT_ID-terraform-state"
terraform plan -var-file=terraform.tfvars
```

Do not run `apply` from a credential-free workstation. The main Terraform
destroy intentionally removes the managed contour but does not remove the
manual state bucket.

## Resource ownership

- Terraform creates datasets only; SQL migrations own BigQuery application
  tables, views, routines and the migration ledger.
- Terraform creates the BigLake catalog and the `bronze`, `silver`,
  `reference` and `audit` namespaces; Spark owns Iceberg table evolution.
- Spark receives direct object access only on the checkpoint bucket. BigLake
  credential vending owns Lakehouse data access.
- dbt receives BigQuery job-user permission and dataset-scoped reader/editor
  permissions; it does not receive broad project-owner access.
